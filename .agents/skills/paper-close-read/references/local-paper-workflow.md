# Local Paper Workflow

本文件覆盖**本地 PDF 分支**的材料准备；arXiv 分支见 [arxiv-md-workflow.md](arxiv-md-workflow.md)，已有可读材料的分支见 SKILL.md。

## Goal

把用户给的单篇本地论文 PDF，整理成一套可写、可插图、可追踪证据的工作目录，而不是直接对着 PDF 生写。

## Recommended Workspace Layout

```text
paper-workdir/
├── source.pdf          # 必备：原始材料副本
├── evidence_map.md     # 必备：claim 与证据映射
├── analysis.md         # 必备：图文精读成品
├── paper.txt           # 可选但推荐：带页码标记的提取文本
└── images/             # 可选但推荐：页面渲染与嵌入图
    ├── index.md
    ├── img-000.png
    ├── img-001.png
    └── ...
```

如果已有更成熟的目录结构，可以兼容，但必备的三样不能少：

- `source.pdf` 或等价原文来源
- `evidence_map.md`
- `analysis.md`

`paper.txt` 与 `images/`（含图片索引）是 PDF 分支的默认工作材料，缺了它们精读质量会明显下降，但不算结构要求。

## Material Preparation Order

### 1. 复制原始 PDF

- 保留原始文件，不要直接在用户源目录里修改。
- 在新的工作目录保留一份 `source.pdf` 或原始文件名副本。

### 2. 提取全文文本

优先顺序：

1. `uv run scripts/prepare_local_pdf.py <pdf> <out-dir>/` —— 默认路径。依赖（PyMuPDF）写在脚本的 PEP 723 头里，`uv` 首次运行时自动解析并缓存，不装系统包、不建 venv、不需要 sudo。
2. 脚本内置的 poppler 兜底（环境里没有 `uv` 时自动触发，能力更弱且无页码标记）
3. 用户已有的提取文本
4. 手工拼接的 OCR 或页面截图

**不要**手动 `pip install` 或 `apt install` PDF 工具来绕开脚本：依赖声明集中在脚本头部，绕开会让环境不可复现。

`paper.txt` 中每页前会有 `===== [page N] =====` 标记，写正文时**直接用它给关键数字标页码**，不要再去数页。

如果提取失败：

- 明确记录当前有哪些材料可用
- 继续寻找同篇论文的已提取文本、副本、笔记
- 不要因为缺少一个工具就直接只看标题和摘要

提取完成后，至少先定位：

- 摘要原文
- 章节标题
- 图号 / 表号
- 关键公式
- 关键数字所在页

### 3. 提取图片或页面

这一步由 `prepare_local_pdf.py` 自动完成，产出两类文件：

1. **`page-NNN.png` —— 整页渲染，200dpi，这是主要材料。** 论文的图表绝大多数是矢量绘制的，整页渲染是唯一稳定可得的视觉材料。要用某张图时，从对应页面渲染里裁出图区。
2. **`img-NNN.png` —— 嵌入位图，只是补充。** 一篇典型的 CS 论文里，PDF 报告的"嵌入图像"往往只是矢量图背后的 soft mask 和阴影层，不是图本身；脚本会把它们与各自的 mask 合成回去，并丢弃合成后仍然是纯色的（那些就是空遮罩）。所以这里可能一张有用的都没有，属正常。

需要更高清晰度时加 `--dpi 300`；页数多、只是通读版式时可以 `--dpi 120` 省空间。

**不要因为 `img-NNN.png` 数量看起来很多就认为图都拿到了**——先实际打开看一眼。历史上这里踩过坑：只提取嵌入图而不渲染页面时，抽出来的 52 张全是打开即纯黑的遮罩层。

小于 120px 的嵌入图会被过滤（分割线、logo、字形碎片）。如果发现某张真图被漏掉了，调 `MIN_IMAGE_PIXELS`，不要改成按文件大小过滤：线条图和图表压缩后可能只有一两 KB。

目标不是“抽尽一切资源”，而是保证这些视觉证据可被正文使用：

- 方法框架图
- 核心表格或主结果图
- 消融图
- 案例图或可视化图

如果论文没有合适的嵌入图：

- 渲染关键页面
- 截图关键表格
- 在索引里注明“页面截图替代原图”

### 4. 生成图片索引

脚本已经写好了文件名、来源页和尺寸，**你需要在此基础上补两列**：对应的图号（Fig./Table）和建议用途。

脚本生成的初始状态：

```markdown
# Image Index

- `img-004.png`: page 5, 1200x800px
```

补全后应变成：

```markdown
# Image Index

- `img-004.png`: page 5, 1200x800px — Fig. 2 方法框架图，用于“方法框架”一节
- `img-007.png`: page 8, 900x600px — Fig. 5 主结果图，用于“主实验结果”
- `img-009.png`: page 9, 400x300px — Fig. 7 案例图，不使用（与核心 claim 无关）
```

如果表格没有单独被提取成图片，也要在证据地图中记录表号和关键数字。

## Figure Usage Rules

- 不能只提“见图 3”，必须解释图支持哪条论点。
- 优先使用原论文图，不要无必要地重画。
- 如果论文图片很多，至少确保方法图和结果图都进入成品。
- 如果论文几乎没有图，允许使用页面截图或文本结构图补位。
- 如果论文只有结果图没有方法图，允许把结果图兼作“方法落地示意”，但必须说明原因。

## Reading Strategy After Preparation

材料准备完成后，按这个顺序建证据地图：

1. 标题、摘要、引言：确定问题、动机、主张
2. 方法章节：圈出关键模块、公式、训练推断流程
3. 实验章节：列出实验问题、数据集、基线、指标、关键表图
4. 结论与讨论：提炼局限、未来方向、适用边界
5. 把主要 claim、图表、关键数字写成简短映射表，避免边写边找

如果论文不是标准实验论文，把第 3 步替换成：

- 实证论文：研究设计、变量、样本、关键表图
- 计量 / 历史论文：时间范围、统计对象、分段方式、关键图表
- 综述 / 理论论文：论点结构、证据来源、作者的归纳边界

## Failure Handling

- 没有文本提取工具：改用已有文本或截图，不中断分析
- 没有图片提取工具：改用关键页面截图，不省略图文结构
- 图号不清晰：在正文里注明“依据页面内容判断”
- 表格 OCR 差：给出能确认的数字和趋势，并注明不确定性
- 没有表格图片：在正文或证据地图里手工摘录关键数字
