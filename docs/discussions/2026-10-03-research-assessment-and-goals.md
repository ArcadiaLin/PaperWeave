# 论文经验管理：候选贡献、验证方案与研究目标

> 记录日期：2026-10-03。本文整合研究水准评估、特色应用、项目经验视图与基线讨论。当前收敛为“两项方法贡献＋一项系统与实证贡献”的候选结构；具体机制、benchmark 和实验协议尚未确定，不能把功能计划当作已成立的创新或实验结论。
>
> 设计依据：[研究顶层设计 v2](../designs/v2/research_design_v2.md)。本文是讨论记录，不自动扩大实现范围，也不授权启动实验。

## 1. 研究定位与整体主线

我们研究面向有界 CS 研究任务的论文经验管理方案：把论文阅读及相关核验形成的知识、解释、关联和证据持久化，支持外部 Agent 在后续任务和新项目中继续使用。

“经验”包括方法及其适用条件、具体实验与结果、资源使用与核验记录，以及带来源的研究判断。外部 Agent 解释任务与材料，判断同一性、适用性、可比性和主张关系；中间件管理这些产物，执行显式提交的访问与更新。读取已存判断与作出新判断必须区分。

整体主线是：

> 持久积累论文经验 → 通过可组合操作访问知识 → 为新项目构建经验视图 → 支持项目内多种研究活动 → 评价复用收益及维护边界。

研究价值既包括中间件的正确性与效率，也包括同一份知识能否服务于多种应用。应用数量本身不构成贡献；如果每增加一个应用都要重新抽取、重设计模型和编写专用流程，就难以证明可复用性。

## 2. 候选贡献与证明责任总览

| 候选贡献 | 核心主张 | 主要验证 | 主要对照 |
| --- | --- | --- | --- |
| C1：论文经验的数据模型与可组合操作机制 | 共同设计表示与操作契约，保留必要语义，减少反复解释和数据衔接 | 固定知识下的正确性、组合行为、交互与执行成本；表示和契约消融 | 同图谱＋Cypher、查询模板及程序编排 |
| C2：面向项目的经验视图构建与复用 | 基于已有子图检索，选择并组织可供项目内多个后续任务使用的知识 | 视图覆盖、上下文完整性、规模、跨任务效果及建设成本 | GraphRAG Local Search、G-Retriever 检索机制、基础 PCST；全局按需访问与结果复用 |
| C3：系统与跨任务复用的实证结论 | 揭示经验管理对实际应用的价值及成本边界 | 从构建到使用的完整评价与受控实验相互印证 | 原始材料 RAG、持久化笔记、通用图访问、无项目视图版本 |

C1 不能只是 schema 和 API 清单，C2 不能只把对话输入换成项目描述，C3 不能只列实现规模和成功案例。如果实证没有产生独立研究发现，C3 应作为前两项的验证部分，而非强行单列贡献。

## 3. C1：论文经验的数据模型与可组合操作机制

### 3.1 候选贡献

通过数据表示与操作契约的共同设计，把反复发生的信息恢复和数据衔接转化为可组合、可检查的数据操作。模型保留对象身份、局部结果对应、条件、来源与版本；操作说明输入、约束、输出绑定，以及缺失、候选和截断状态。

需要回答：哪些信息必须显式表示，哪些适合保留文本；组合如何保留原有含义；哪些步骤可由数据和规则完成，哪些仍需外部新判断。属性图与 Cypher 是实现基础，不要求另建数据库、提出超越 Cypher 的表达力或完整新代数。

### 3.2 验证方案与 baseline

| 验证问题 | 实验设计 | Baseline |
| --- | --- | --- |
| 专门操作接口是否有价值？ | 固定知识、模型与可比预算，检查访问结果、修正次数和成本 | 同一图谱＋充分说明的 schema＋Agent 编写 Cypher |
| 是否只是查询模板封装的收益？ | 在多步组合中检查条件、绑定、来源与版本的传递 | 同图谱＋合理设计的参数化查询模板／辅助函数 |
| 收益是否只来自普通程序编排？ | 两侧均允许代码执行、批量调用及结果复用 | 同图谱＋查询模板＋程序编排 |
| 哪些设计真正有用？ | 针对性移除绑定、条件保留或组合检查，定位错误及成本变化 | 我们方案的消融版本 |

固定知识的比较主要隔离接口和操作机制。评价表示本身时，需要从相同事实与证据构造不同表示，说明信息损失与构建投入。原始材料 RAG 可用于整体比较，不能独自证明算子有效。

评价须区分意图符合性、计划契约有效性、后端执行正确性，以及知识和判断的证据支持。除最终答案外，还需检查返回记录、局部对应、条件和来源。减少工具往返、减少重新规划与减少新语义判断工作量分别记录；批量提交判断不代表判断消失。

## 4. C2：面向研究项目的经验视图构建与复用

### 4.1 应用定义与数据库问题

**研究项目知识初始化（Research Project Knowledge Bootstrapping）**：给定新项目的目标、范围与资源约束，从全局论文经验库中选择并组织相关知识，形成可供后续方法筛选、实验比较和资源准备等活动复用的项目经验视图。

例如，在有限标注和单卡条件下改进领域文献检索，项目可能需要相关方法、实验条件与结果、数据及指标、实现版本和核验记录，也需要知道哪些条件尚不明确。

全局库面向持续积累，项目面向有界需求。保存知识并不自动解决如何取得合适起点的问题。选择相关节点可能遗漏解释所需的条件与依据；取完整邻域则可能带入大量无关信息。项目视图需要研究选择、上下文补全与规模之间的关系。

暂用“经验视图构建”而非严格的“投影”：产物可能包含选择、关联、分组、缺失说明和来源引用，不一定是原图的诱导子图。**“项目子图优于总图”是待检验假设。** 合理的全局访问会按需查询，并不会把整张图放入模型上下文。

### 4.2 已有方法与适配方向

当前倾向沿用已有子图检索，不另起一条通用图检索算法研究线。主要外部对照集中在 GraphRAG Local Search 与 G-Retriever；SIGDIAL 2025 的 *Retrieving Relevant Knowledge Subgraphs for Task-Oriented Dialogue* 作为方法借鉴来源。

该论文明确借鉴 G-Retriever：将图元素文本化、计算相关性，再用 Prize-Collecting Steiner Tree（PCST）构建子图，使用 `pcst_fast` 实现，无需额外训练检索模型。其连通性要求不等同于论文经验的上下文完整性。[论文 §2–3](https://aclanthology.org/2025.sigdial-1.42.pdf)

| 部分 | 当前处理方向 |
| --- | --- |
| 相关性评分与 PCST 求解 | 借用已有技术并明确归因，不作为我们的原创算法 |
| 输入 | 从当前问题／对话适配为项目目标、约束和所需知识角色 |
| 选择对象 | 使用论文经验对象及其关系 |
| 上下文要求 | 候选方向是保留必要条件、结果绑定、来源和版本，具体规则待定 |
| 输出 | 形成结构化项目视图，供多个后续任务使用 |
| 生命周期 | 保留与全局库的联系；快照、动态视图或受控更新尚未选定 |

两个适配问题需先检查：图上连通不保证必要条件与证据完整；项目可能包含独立技术路线，不一定需要所有知识整体连通。不能为迁就 PCST 强行加入无意义的路径。是否调整选择方式，须由实例支持。

### 4.3 候选 pipeline

| 阶段 | 职责 | 输出 |
| --- | --- | --- |
| 项目需求表达 | 外部 Agent 将目标解释为主题、显式约束、知识角色和预算 | 可修改的需求规格 |
| 候选发现 | 根据文本、对象及关系召回知识 | 候选记录与匹配依据 |
| 选择与上下文补全 | 用已有选择器及待设计的契约规则组织结果 | 候选视图和缺失说明 |
| 视图建立 | 保存成员、来源引用、版本及选择记录 | 可被后续操作使用的项目视图 |
| 使用与必要维护 | 支持访问与补查；若实现更新机制，则识别受影响部分 | 使用轨迹、更新或待复查记录 |

适用性等开放判断仍由外部 Agent 完成。中间件保证的是相对于显式依赖和契约的性质，不能宣称自动判断所有语义上下文是否充分。pipeline 的阶段数量不构成贡献；项目视图不要求复制整个图或自动回写项目中的所有新判断。

#### 4.3.1 选择带上下文的知识，保留局部绑定

结合 SIGDIAL 2025 子图检索论文的精读，当前候选设计是：**C1 定义哪些绑定、条件和依据必须保留，C2 在选择与裁剪项目视图时遵守这些契约。** 以下记录功能方向，不代表具体规则、算法和实现范围已经确定。

例如，项目目标是“有限标注、单卡条件下改进文献检索”，召回“方法 A 在数据集 D 上取得 0.82”还不足以使用该经验。视图需要保留对应的方法变体、数据切分、指标、实验配置、标注规模、资源条件与证据位置；哪些属于必要上下文，应由具体知识角色和操作契约明确，而非对所有对象无差别补齐全部字段。

选中一个结果后，应沿已存的显式依赖带回解释该结果所需的记录，并保持方法、配置与分数的局部对应。这里的“补全”是取得已有上下文；缺少资源条件或证据时返回缺失说明，不由检索算法猜测或生成事实。完整性保证只相对于声明的依赖和契约成立。

#### 4.3.2 分开候选发现、结构选择和上下文检查

| 功能 | 职责 | 边界 |
| --- | --- | --- |
| 候选发现 | 按项目需求召回方法、结果、资源及已有判断，返回匹配依据 | 不把相关性当作适用性结论 |
| 结构选择 | 在预算内选择候选及有用关联，可借用基础 PCST | 不保证选中结构在语义上充分 |
| 上下文补全与检查 | 按显式依赖取得必要条件、绑定、来源和版本，检查缺失 | 不生成新的科学判断 |

三项职责应可分别观察和替换，以便区分评分器、结构选择和上下文规则各自的效果。逻辑上分开并不要求一次线性执行；选择与补全是否需要迭代，取决于预算处理机制。

**预算必须考虑补全后的成本。** 单个候选节点很短，其必要实验条件和证据却可能很长；先按节点数选满再无条件补全，可能超出预算。需要用实例确定如何估计依赖展开成本、处理共享上下文，以及在预算不足时重新选择或明确返回未满足的要求。不能静默裁掉必要条件后仍声称视图完整，也不能将少量节点等同于较小 token 成本。

#### 4.3.3 允许多个独立知识组

项目可能同时比较稀疏检索与稠密检索等独立技术路线。它们都与项目有关，却未必存在值得保留的连接路径。为了整体连通而加入同年份、同领域等公共节点，可能只增加规模。

候选输出契约因此允许项目视图包含多个知识组：各组保留契约要求的上下文，组间联系有明确用途时再纳入。分组依据来自显式需求、已存关系或外部 Agent 提交的判断，不要求中间件自行理解技术路线。暂不决定采用多次 PCST、森林选择还是其他实现，先检查单一连通约束在真实实例中是否造成遗漏或无用扩展。

#### 4.3.4 返回条件状态和依据，区分缺失与新判断

以“单卡可运行”为例，候选返回信息至少需要表达下列区别；具体编码尚未确定，也不预设为互斥且完备的四值枚举。

| 状态或说明 | 含义 |
| --- | --- |
| 有记录支持 | 对应版本和配置存在支持该条件的运行、核验记录或显式判断；注明证据类型 |
| 有记录不满足 | 对应版本和配置有明确不满足条件的记录或判断 |
| 信息不足 | 当前可访问记录不足以判断，不等于条件不满足或没有资源要求 |
| 需要新判断 | 已有相关材料，但仍需外部 Agent 判断是否适用于当前项目 |

中间件可以执行明确的字段约束、读取已有判断并返回来源；涉及开放适用性时交给外部 Agent。论文声称可运行、仓库具有相关文件、实际成功运行仍须区分。相互冲突的记录应保留各自条件与依据，不能强制折叠成单一支持状态。

#### 4.3.5 保存成员的选择依据与依赖

视图成员应能说明为什么被纳入，候选原因包括：直接匹配项目需求、为解释另一条记录而补入、连接其他选中记录。同一成员可以具有多个原因。

相应保存需求引用、依赖对象、来源与版本引用，以及选择器或规则的记录。后续操作据此解释成员用途、追溯结果，并为可能的影响检查提供依据。保存这些信息不意味着已经实现自动刷新，也不预先决定视图采用快照还是动态引用；生命周期协议仍待选择。

#### 4.3.6 第一版候选范围与证明责任

第一版优先明确：**显式项目需求 → 候选召回 → 选择与必要上下文补全 → 带来源、缺失说明和选择依据的项目视图。** PCST 可作为基础选择器；自动适用性推断、复杂动态维护和新的通用图检索算法不由这次借鉴自动进入范围。

SIGDIAL 论文提供了有限的借鉴依据：BM25 设置下测试 F1 从 0.398 提升至 0.425，但用户研究中基线与 PCST 的比较未达到统计显著；附录的高用户评分也不能替代证据支持和实际任务执行核验。这些结果支持把结构选择作为候选机制，不证明我们的项目视图有效。[论文 Table 1、Table 3、Appendix B](https://aclanthology.org/2025.sigdial-1.42.pdf)

对应本设计，优先验证三个问题：

1. 选择与补全后，方法、配置、分数、条件和证据是否仍正确绑定？
2. 在可比预算下，上下文规则是否减少条件遗漏与错误使用，收益来自哪些规则？
3. 视图能否支持初始化时未直接给出的后续任务，且累计收益覆盖初始化与补查成本？

下一步仍是用一个真实项目实例列出需求、必要上下文、参考输出和基础方法的具体缺口，再确定最小契约及实现机制；本节不授权启动实验。

### 4.4 验证构建方法是否有效

给定相同项目输入和知识源，使用同一后续 Agent 与可比预算，检查知识覆盖、必要上下文完整性、视图规模及后续任务效果。

| Baseline | 比较目的与适配说明 |
| --- | --- |
| GraphRAG Local Search | 比较已有图上下文构建方式；说明实体、关系、原文及报告的映射和额外建设成本 |
| G-Retriever 检索机制 | 比较已有子图选择机制；只复用检索组件时明确称为适配版本 |
| 基础 PCST pipeline | 保持项目输入、评分器和知识库一致，移除我们的扩展，检查改动作用 |

如果基础 PCST 与适配后的 G-Retriever 实质重复，可合并。无需完整重建 SIGDIAL 论文的对话系统，但直接借用的方法必须引用，并保留能检验改动价值的基础版本。基线取舍依据方法相关性和比较作用，不以被引量作为排除理由。

可以统一不同选择器的输出格式和项目存储方式，再消融上下文补全等机制，避免把存储能力或输出格式差异误认成选择算法收益。简单 top-k 或限定跳数扩展可作诊断对照，不要求无限增加基线。

### 4.5 验证项目视图是否值得建立

构建方法比较不能替代访问策略比较。关键对照是：**直接按需访问全局经验库，并允许保存项目笔记、已发现对象与查询结果**。不能只比较“基线每次重找”和“我们提前整理并保存”。

候选评测流程：

1. 初始化只给项目启动时可知的目标与约束，不暴露全部后续题目。
2. 执行多个后续任务，检查视图是否能跨任务复用。
3. 各方案均允许合理补查全局库，并计入补查与上下文成本。
4. 累计初始化及使用成本，观察收益随使用次数和任务重合程度的变化。
5. 若维护进入正式贡献，再引入知识变更，检查影响识别与修复成本。

固定视图、禁止补查可作为覆盖诊断，但不宜作为唯一的应用比较。相同节点数不等于相同信息预算，应同时报告 token、存储规模、时间与质量。若初始化已获得全部后续问题，应表述为已知查询集合的预计算，而非一般的新项目初始化。

## 5. C3：系统与跨任务复用的实证结论

### 5.1 特色应用与输出

系统需要说明同一份经验能支持什么实际工作。QA 可作为基础访问任务，但不宜仅用长答案评分覆盖全部能力。以下是候选应用，并非全部实现要求。

| 应用 | 主要输出 | 体现的管理能力 |
| --- | --- | --- |
| 带条件的方法筛选 | 候选、条件满足情况、未知项与依据 | 方法、资源和实验经验的联合利用 |
| 实验结果对齐与比较 | 条件化比较表、设置差异与证据 | 结果与方法、数据、指标和配置的局部绑定 |
| 评测方案准备与检查 | baseline、数据及指标建议，理由与待确认条件 | 将已有评测经验用于新任务 |
| 实现与复现准备 | 实现、版本、配置、核验状态和障碍 | 论文声明与实际资源记录的关联 |
| 证据综合与分歧分析 | 主张—条件—证据对照及未解决分歧 | 跨论文关系组织与限定保留 |
| 更新后的影响检查 | 受影响记录及产物、依据和待复查项 | 显式依赖、版本与维护；需另有机制支持 |

初始应用可从实验比较、评测方案准备、实现资源准备中收敛。项目初始化是这些应用的共同入口。科学发现或实验成功不作为中间件保证；例如评测方案可以检查覆盖、依据和条件一致性，不必承诺产生优秀研究结论。

### 5.2 验证方案与 baseline

| 验证问题 | 验证方案 | Baseline |
| --- | --- | --- |
| 持久化经验是否值得建设？ | 从材料构建到多次使用，检查质量与累计投入 | 原始材料混合检索 RAG、持久化论文笔记＋检索 |
| 是否需要专门管理机制？ | 固定已存知识，比较多种应用 | 属性图＋Cypher／模板＋程序编排 |
| 项目视图是否有额外收益？ | 同一系统、同一任务序列比较有无视图 | 我们的模型与算子，直接访问全局库并复用已有结果 |
| 何时收益覆盖成本？ | 改变复用次数、任务重合程度；维护纳入范围时，再改变更新负担 | 各方案累计建设、使用、补查和维护成本 |

固定知识的受控实验解释机制；完整实验解释实际收益。后者须计入抽取、规范化、索引与视图建设，不得把更好的知识输入产生的效果全部归于算子。应用结果需要独立质量判断，不能只以流畅答案或模型自评为依据。

## 6. 贯穿三项贡献的四个研究问题

### 6.1 哪些论文知识值得结构化保存，哪些保留文本更合算？

检查哪些身份、关系、条件与结果对应会反复参与过滤、连接、分组和更新，哪些机制描述与开放解释适合保留文本。比较访问收益、遗漏、错误结构化及建设维护成本，不以字段完整度或节点数量代替价值。预期产出是带适用条件的表示设计原则。

### 6.2 哪些中间步骤可以用显式数据与规则替代，哪些仍需要新判断？

区分确定性处理、读取已有判断、新语义判断与重新规划。检查反复解释源于表示缺口，还是任务本身需要新理解。旧判断复用须保留适用范围；减少往返不等于减少判断。预期产出是连续执行的机制与边界。

### 6.3 哪些组合容易产生条件、版本或结果对应错误，怎样避免？

典型风险包括：同名 benchmark 的不同切分混淆、跨版本核验结果误用、同一报告中的方法与分数错误交叉组合、来源和限定丢失，以及把缺失当否定。这些风险也适用于视图裁剪。用独立参考绑定和困难样例检查契约，不以图连通、schema 合法或附带链接代替语义正确性。

### 6.4 在什么复用频率和更新负担下，建设这层中间件才值得？

比较完整生命周期成本，考察任务间知识重合、知识变化速度与修正难度。分别报告时间、模型使用、数据库执行和必要人工投入。允许得出某些场景更适合文本或轻量表示的结论，不能通过降低质量制造成本优势。维护协议未确定前，不宣称已验证长期更新收益。

## 7. 公平比较与基线组织

基线可共享实现，但不同层次不应强行汇总为一张排行榜。

| 比较层次 | 需控制的因素 | 主要解释 |
| --- | --- | --- |
| 同知识的访问与组合 | 知识记录、模型、工具能力、编排和预算 | C1 的操作机制价值 |
| 项目视图构建 | 项目输入、可访问知识、评分与选择差异、输出和后续 Agent | C2 的构建机制价值 |
| 项目内任务序列 | 初始化信息边界、任务集合、补查与结果复用权限 | 预先建立视图是否值得 |
| 完整建设与使用 | 原始材料访问、模型与人工投入、质量标准和成本口径 | 整体方案的适用性与成本边界 |

特别避免：给我们的方案更完整知识却归功于接口；禁止基线保存结果；只统计后续查询成本；用设计时看过的全部问题证明项目泛化；把外部推理改善算成中间件执行改善。

任务需求应独立于候选模型确定。数据状态、参考输出、失败情形、随机性与预算须可追溯。强基线下没有收益时，应修正主张或收缩贡献，不能仅换弱基线。

## 8. 论文叙事与章节候选

论文围绕“持续积累如何转化为新项目可复用的知识”组织：模型与算子提供基础，项目经验视图集中展示机制，特色应用检验用途。

| 章节 | 主要内容 |
| --- | --- |
| Introduction | 从项目启动与知识复用困难引出问题、方案和经验证实的贡献 |
| Workload and Problem Formulation | 有界任务、初始化信息、所需输出、责任边界与正确性目标 |
| Semantic Data Model and Composable Operations | 表示选择、对象与绑定、操作契约及组合规则，共同解释 C1 |
| Project Experience View Construction | 借用的选择器、项目适配、上下文组织、视图建立及补查策略，解释 C2 |
| System Implementation | 契约到图查询、索引与材料访问的映射，简述实现 |
| Evaluation | 正确性与机制实验、视图比较、应用序列及生命周期成本 |
| Related Work | 学术知识管理、结构化记忆、图检索、视图与程序化数据访问 |
| Conclusion | 已证明的收益与适用边界 |

用一个贯穿实例解释设计，用其他任务和组合检验复用。维护只有形成机制和证据后才突出为技术内容，不为叙事完整而扩成独立研究线。

## 9. 研究水准与发表目标

SIGMOD 保持为目标。当前路线有合理潜力，但实现完成和指标上升不足以保证达到录用门槛。

| 最终证据 | 条件性评估 |
| --- | --- |
| 建图、封装接口，优于普通 RAG；项目视图仅替换检索输入 | 有应用价值，尚不足以单凭这些支撑 SIGMOD 级贡献 |
| 相对合理查询模板与编排有可归因收益，项目视图适配解决具体困难 | 形成实质研究贡献，可以认真冲击 SIGMOD |
| 在未参与设计的实例或组合中仍有效，并解释质量、规模与生命周期成本边界 | 更接近有竞争力的完整系统研究 |

不要求所有指标获胜，也不要求覆盖所有科研行为。其他 CCF A 场所可根据最终贡献与拒稿原因考虑，不能视为保底；封装性强、弱基线或任务定制问题不会因换场所自动消失。即使未达顶会要求，对四个核心问题给出可靠且可复现的答案，仍可以构成不错的研究。

## 10. 尚待确定与下一步

当前倾向是借用已有子图检索，集中精力于论文经验表示、操作和项目复用。以下事项仍需讨论：

1. 选择哪个真实 CS 项目，启动时已知哪些约束，后续有哪些可独立评价的任务？
2. 第一版视图需要哪些知识角色、绑定和上下文？哪些缺失必须报告？
3. 基础 PCST 在该实例中出现什么具体问题？我们的最小改动是什么？
4. 视图采用快照、引用还是其他方式；维护是否进入初始贡献范围？
5. GraphRAG 与 G-Retriever 如何映射到同一知识源，哪些适配会改变原方法？
6. 独立质量标准、建设成本和任务序列预算如何确定？

下一步优先用一个真实实例明确需求、参考输出和基础方法的差距，再确定最小机制与实验范围。此处不直接启动实现、训练或全语料运行。

## 11. 方法与评估参照

以下为讨论中已查阅的来源，不代表完整相关工作审查，也不证明候选贡献具有新颖性。

- [GraphRAG Local Search](https://microsoft.github.io/graphrag/query/local_search/)：图与文本上下文构建的主要候选对照。
- [G-Retriever](https://arxiv.org/abs/2402.07630)：PCST 子图检索的重要来源；区分完整系统与检索组件适配。
- [Retrieving Relevant Knowledge Subgraphs for Task-Oriented Dialogue](https://aclanthology.org/2025.sigdial-1.42/)：拟借鉴的轻量 pipeline，沿用已有技术需明确归因。
- [Beyond Context Windows: Persistent Discovery Context for Data-Centric Agents](https://arxiv.org/abs/2609.02129)：复用意图与数据对象对应关系的近邻工作，尚未精读或确定为基线。
- [PostgreSQL Materialized Views](https://www.postgresql.org/docs/current/rules-materializedviews.html)：持久化查询结果与刷新是已有能力，视图概念本身不能作为创新。
- [SIGMOD 2027 Research CFP](https://2027.sigmod.org/calls_papers_sigmod_research.shtml)、[PVLDB 2027 Research Track](https://www.vldb.org/2027/call-for-research-track.html)、[CCF 推荐目录](https://www.ccf.org.cn/Academic_Evaluation/DM_CS/)：投稿要求与类别参照，不构成录用或质量保证。
