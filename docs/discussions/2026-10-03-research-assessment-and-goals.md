# 项目研究水准评估与目标

> 记录日期：2026-10-03。本文记录对当前研究路线的条件性评估，以及希望研究最终回答的问题。发表潜力判断不是录用预测；以下目标也不代表机制已实现或效果已验证。具体 benchmark、实现范围与评测协议仍需讨论确定。
>
> 设计依据：[研究顶层设计 v2](../designs/v2/research_design_v2.md)。

## 1. 总体评估

当前项目有成为 SIGMOD 级研究的合理潜力。如果数据模型与算子的核心假设经受住强基线和完整评测，可以达到值得认真竞争录用的水准。但系统实现完成、实验指标符合预期，本身不足以保证达到这一门槛：还需要说明贡献的重要性、新颖性，以及收益究竟来自什么机制。

研究对象已经能够落到具体的数据管理问题：外部 Agent 产生的论文衍生知识，在持久积累和多步使用时，如何保留对象身份、局部对应、条件、来源与版本，同时降低反复解释和组织数据的成本。这个问题可以独立于某个模型或问答系统成立。

目前最值得发展的候选贡献是：

> 通过数据表示与操作契约的共同设计，把反复发生的信息恢复和数据衔接转化为可组合、可检查的数据操作，并解释这种转化的收益、成本和边界。

这一路线不要求开发全新的底层数据库，也不要求提出比 Cypher 更强的语言。关键在于形成可复用的抽象和机制，而非仅增加节点类型或封装工具接口。贡献是否成立，仍须对照已有研究和有竞争力的实现进行验证。

## 2. 研究最终应回答的四个问题

下面四个问题是评价研究价值的重要目标。它们用于指导范围收敛和证据组织，不要求一次实现全部候选机制，也不预设答案一定有利于结构化中间件。

### 2.1 哪些论文知识值得结构化保存，哪些保留文本更合算？

需要解释表示粒度的选择依据：哪些身份、关系、条件与结果对应会被反复用于过滤、连接、分组和更新，因而值得显式表示；哪些机制描述、限定和开放解释更适合保留文本，并在需要时交给外部 Agent 阅读。

可考察的例子包括资源身份与版本、实验结果与设置的局部绑定，以及方法机制的自然语言描述。这些例子只是候选，不能先假定某一类信息必须全部结构化。

希望得到的研究产出是有适用条件的表示设计原则：结构化带来哪些访问与正确性收益，又增加多少抽取、规范化和维护负担。比较应同时考察遗漏、错误结构化和文本解释成本，避免以节点数量或字段完整度替代实际价值。

### 2.2 哪些中间步骤可以用显式数据与规则替代，哪些仍需要新判断？

需要逐项区分确定性数据处理、读取已有判断、新语义判断，以及执行策略的重新规划。例如，按明确版本连接记录、按已有状态筛选和装配来源，可以由程序执行；未有充分记录时判断两个实验是否可比，仍需要外部解释与判断。

重点是检查：哪些反复解释源于表示或接口缺口，补充显式数据后能否消除；哪些判断依赖新材料、新条件或开放语义，不能由固定规则承担。读取过去的判断也必须检查其适用范围，不能默认它对新任务仍然有效。

希望得到的研究产出是可说明边界的连续执行机制。评测须区分工具往返减少、重新规划减少与新语义判断工作量减少；批量调用降低往返，并不自动证明判断本身减少。预先整理知识的成本也应计入。

### 2.3 哪些组合容易产生条件、版本或结果对应错误，怎样避免？

需要识别多步访问中的具体失真方式，例如：

- 同名 benchmark 的不同切分或评测设置被混为一谈；
- 某个资源版本的成功运行记录被附到另一版本；
- 同一实验报告中共同出现的方法、数据集和分数被错误交叉组合；
- 候选检索、过滤和结果装配后，来源、限定或截断状态丢失；
- 缺失记录被解释为否定事实，已存支持关系被当作新的结论证明。

需要研究哪些错误可以通过类型、稳定引用、结果绑定、来源与版本契约，以及显式的缺失状态加以预防或检测。涉及现实含义的错误仍需外部判断；契约检查通过不等于知识内容真实，也不等于 Agent 提交的计划符合用户意图。

希望得到的研究产出是可检查的组合规则及其适用边界，并用独立参考结果和困难实例验证。仅证明单个算子返回正确，或结果附带证据链接，还不足以证明组合保留了原有含义。

### 2.4 在什么复用频率和更新负担下，建设这层中间件才值得？

需要比较完整生命周期的投入与收益：初始抽取与整理、身份规范化、索引和视图建设、后续查询，以及增量更新、修正、撤回和失效处理。

复用次数之外，还应考虑不同任务之间的知识重合程度、知识变化速度和修正难度。大量重复访问稳定知识，与少量访问持续变化的知识，可能得到不同结论。单次查询更省 token 或调用次数更少，不足以证明建设成本能够收回。

希望得到的研究产出是质量约束下的成本边界：在什么条件下更合算，收益何时出现，哪些情况下文本访问或较轻的表示更合适。成本应分别报告时间、模型使用、数据库执行和必要人工投入，明确核算口径；不能通过降低结果质量制造成本优势。

## 3. 发表目标与贡献层次

SIGMOD 保持为目标，但不将“完成全部工程与实验”直接等同于“达到录用要求”。下面是当前讨论中的判断尺度，不是会议官方评分表。

| 最终能够证明的事情 | 对研究水准的条件性判断 |
| --- | --- |
| 建立论文知识图谱并提供工具接口，比直接读论文或普通 RAG 更好 | 有应用价值；单凭这些，尚不足以支撑 SIGMOD 级贡献 |
| 在同样知识、模型与可比预算下，相对充分说明的 Cypher、查询模板和程序编排，获得来自表示与组合机制的可靠收益 | 形成实质研究贡献，可以认真冲击 SIGMOD |
| 进一步解释机制为何有效，在未参与设计的任务组合、不同数据状态及更新过程中仍成立，并揭示成本与适用边界 | 更接近有竞争力的完整系统研究 |

不要求所有指标都获胜，也不要求推广到所有科研任务。需要在声明的范围内证明重要、可信且可解释的收益，并诚实报告代价和失败情形。

如果 SIGMOD 未录用，应根据具体原因判断后续路径。如果机制与证据扎实，争议主要在贡献重要性、受众匹配或论证方式，可以考虑 VLDB、ICDE，或发展为 TKDE、VLDB Journal 的完整论文。如果核心问题是直接封装已有技术、最强基线下收益消失，或任务过度围绕自有模型定制，则需要补足贡献，换投稿场所不会自动解决问题。其他 CCF A 不是保底。

即使没有达到这些场所的要求，只要能够对上述四个问题给出可靠、可复现且有边界的答案，帮助其他研究者做出更好的系统设计，仍然可以是一项不错的研究。反之，仅凭系统规模、实现工作量或若干成功案例，不能认定研究质量。

## 4. 关键质疑与证据目标

| 需要回答的质疑 | 应提供的证据 |
| --- | --- |
| 是否只是领域 schema 加若干查询模板？ | 明确可复用的机制，展示在组合、绑定或维护中的具体作用；比较合理设计的模板方案 |
| 收益是否来自提前投入更多知识整理？ | 同知识受控比较，另行评价包含构建、规范化和维护成本的完整过程 |
| 连续执行收益是否只是普通程序编排带来的？ | 基线也允许代码执行、批量调用与合理模板，隔离模型和算子契约的贡献 |
| 任务是否为自有模型量身定制？ | 任务依据独立于候选模型，使用未参与设计的实例或组合，并记录覆盖边界 |
| 正确性是否仅指格式与 schema 合法？ | 分别检查计划意图符合性、契约有效性、执行正确性，以及知识和判断的证据支持 |

优先验证一个核心机制能否在最有竞争力的对照下成立，比继续扩充功能更能判断项目上限。候选下一步是选择一个具体组合实例，固定输入、数据状态和独立参考输出，明确失真风险、机制差异与公平对照。实例和实验方案需另行讨论确定。

## 5. 评估参照

以下来源用于说明投稿要求和场所类别，不构成项目已达到相应水准的证据。

- [SIGMOD 2027 Research CFP](https://2027.sigmod.org/calls_papers_sigmod_research.shtml)：要求实质创新；实验完整不能替代贡献本身。
- [PVLDB 2027 Research Track](https://www.vldb.org/2027/call-for-research-track.html)：系统论文可以以新抽象、系统设计及有效技术组合为创新，并不普遍要求理论证明。
- [CCF 数据库／数据挖掘／内容检索推荐目录](https://www.ccf.org.cn/Academic_Evaluation/DM_CS/)：用于核对相关会议和期刊的分类，分类本身不是录用难度或论文质量的保证。
