# 论文抽取原则

> **状态：** 草案（2026-10-03）。规定外部 Agent 读一篇论文时抽什么、抽到多深、怎样写进入库表单；表单如何编译成增量、由 `Commit` 检查与写入，见 [Commit 契约](./commit_contract.md)。第 1–9 节已与用户确认（2026-10-03），第 10 节为待定事项。**2026-10-03 修订**：第一个 I3 实例试跑后，实验改为按研究问题分组、只入库语义描述与定位（第 4 节），去掉变体标签、条件复述、疑点与逐项来源性质（第 2、5、6 节）；按表录入的上一版及两篇论文的入库表单见提交 `781832d`，行级做法见 `f95631b`。

抽取由外部 Agent 完成，中间件只做确定性的编译与检查（[研究顶层设计](./research_design_v2.md)、[Workload 拆解](./intents_decompose.md) §5 写路径）。本文回答 Agent 一侧的问题：一篇论文读完，哪些内容以什么粒度进入图。

## 1. 单篇深度：只抽到论文自身（已定，2026-10-03）

一篇论文的抽取只做到**它自身陈述的深度**。别的方法、别的论文的内容，要读它们自己的原文才能得到准确信息，不在本篇的抽取里代为完成。

| 内容 | 本篇抽取做什么 | 不做什么 |
| --- | --- | --- |
| 本文提出的方法 | 建**一个**核心方法节点，写定义 | 不为变体、消融配置另建节点 |
| 被对比的方法（基线） | 建**桩节点**：名称与引用线索 | 不写定义，不建它与其他方法的关系 |
| 本文怎样使用基线 | 参与角色写在实验的参与边上；基线的结果引自哪篇论文写成 `CITES`（第 5、8 节）；需要时在实验描述中一句话说明 | 不逐表记录变体标签、回看窗口与每个数字的来源，这些按锚点读原文 |
| 被引论文 | 建 **Paper 桩节点**：参考文献中印的标题与引用线索；本文对它的实质依赖写成 `CITES`（第 8 节） | 不写摘要，不抽它的实验 |
| 方法之间的语义关系（属于哪一类、由什么机制组成、继承谁） | 默认不抽 | 只有论文明确陈述且某个 intent 需要时才写，见第 7 节 |

划分依据是**信息出自谁的陈述**。"FEDformer 在本文表中取 $L=96$、数字由作者转引"是本文的陈述，属于本文的实验；"FEDformer 是什么方法"要读 FEDformer 原文，属于将来 FEDformer 论文的抽取。

## 2. 核心方法与变体（已定，2026-10-03；2026-10-03 修订）

- 每篇论文只抽它的核心方法作为 `Concept.Method`。DLinear 一文只有 `DLinear`，PatchTST 一文只有 `PatchTST`。
- 变体与配置（DLinear-S / DLinear-I、PatchTST/64 / PatchTST/42、FEDformer-f / FEDformer-w、有无实例归一化）**不建节点，也不在结构中记录标签**。理解实验所必需的变体，在实验描述（`text`）中用一句话说明，例如 "PatchTST/42 (look-back 336) is the paper's fair comparison to DLinear"；其余按锚点读原文。
- 名称级的独立方法（后续工作单独引用、另有演进，如 FlashAttention-2）不按变体处理，单独建节点，按 [Graph Model V2](./graph_model_v2.md) §2.3 的名称级差异处理。

**依据。** 变体节点让读者看到 "DLinear-I" 仍要回原文核实，节点本身不省阅读；而且必须靠 `BROADER` 才能把变体接回母方法。`BROADER` 因此不承担变体（[Graph Model V2](./graph_model_v2.md) §3.1）。上一版把原文印的变体标签记在参与边上（`variants`）；试跑中 Agent 仍要读表确认标签对应哪一列，标签与条件复述一样没有省下阅读（第 4 节）。

## 3. 被对比方法：桩节点（已定，2026-10-03）

实验的参与边需要可引用的被测对象，跨论文的同一基线也必须落在同一节点上，才能找到所有报告过它的实验（例如 PatchTST 重跑的 FEDformer 与 DLinear 表中的 FEDformer-f）。所以被对比的方法建节点，但只建桩：

| 字段 | 桩节点写什么 |
| --- | --- |
| `name` | 原文使用的名称；只注册原文确实用过的称呼 |
| `definition` | 留空。桩节点写定义视为错误 |
| `note` | 引用线索，例如 `Cited as [29] Zhou et al., FEDformer: Frequency enhanced decomposed transformer …` |
| 标记 | `stub`，表示"尚未读原文"，而不是"没有可说的" |

- 后续论文用到同一基线时，在 alias 级命中这个节点，不重复创建。
- 这篇基线论文本身入库时，用 `fill` 补全同一节点：只填空字段并去掉 `stub`（[Commit 契约](./commit_contract.md) §3）。
- 引用线索不写进 `identifiers`：论文的 arXiv 号标识的是论文，不是方法。以后若要表达"方法由哪篇论文提出"，随 `INTRODUCES`（Graph Model V2 §7 第 14 项）一起定。

## 4. 实验：按研究问题分组，只入库描述与定位（已定，2026-10-03 修订）

图的收益来自**发现**：一个问题该去哪些论文、哪些实验、哪些表图里找。具体数值、条件细节与逐格对应留在原文，由 Agent 按锚点细读。所以实验节点只记录三类内容：

| 内容 | 去处 |
| --- | --- |
| 这组实验为了回答什么、怎样设计、论文据此声称了什么 | 实验描述：Experiment 的 `text`（Content 类统一的描述字段，[Graph Model V2](./graph_model_v2.md) §4.2） |
| 在原文哪里：结果表、图，以及陈述设计与结论的正文 | `anchors`（表、图的锚点列表，第一个为主锚点）；`FROM` 的 locators（全部行范围，含正文） |
| 和谁有关：被测方法及其角色、数据集、指标、任务 | `EVALUATES {role}`、`USES {role: evaluation_data}`、`MEASURED_BY`、`ON_TASK` |

**分组。**

- 一个 Experiment 是论文结果部分里的**一个研究问题**，例如主结果对比、消融、效率、长回看窗口、训练数据量。划分以论文自己的结果小节和行文为准，写法参考 paper-close-read 的实验分析（"作者想证明什么 → 如何设计 → 证据是否足够 → 结论能说到哪一步"）。
- 一组可以跨多张表、图和正文段落。附录中补全正文某张表的 "full benchmark" 并入那张表所在的组；只用图报告的实验同样入库。
- 不为单个数据集、指标或预测长度拆分。

**实验描述（`text`）的写法。** 两到五句英文，用自己的话概括，不转录：

1. 目的：这组实验要回答的问题或验证的主张；
2. 设计：比了谁、在什么范围的数据上，以及理解这组实验**必需**的条件或变体，一句话带过（例如两边的回看窗口不同、基线结果引自他人论文）；
3. 结论：**论文声称**证明了什么，写成 "The paper reports / claims …"，与核验分开。

不写具体数值、不复述表格、不写入库者自己的疑点或评价（第 6 节）。

**为什么这样改（2026-10-03，I3 试跑）。** 上一版每张结果表一个 Experiment，并在节点上写 `text`、条件复述 `setting`、疑点 `note`、变体标签与逐项来源性质。Q1 试跑表明：

- 一次 `Experiments` 返回 46,010 字符，其中复述文字 12,882 字符；Agent 读完后仍要读表核对（455 行），复述既没有替代阅读，又多付一次 token。
- Agent 把入库时写的 `note` 当成"原文的说法"写进回答。入库者的判断与原文陈述混在一个节点里，读者无从区分。
- `note` 中记录的疑点恰好是评测题要考的内容，构成泄露。
- 真正起作用的是定位：哪篇论文、哪张表、结果引自哪里。

**为什么不录数值、不录条件。** 数值照抄并不难，难的是每个数对应哪个方法、变体、数据集与条件，这正是 Agent 读原文时要做的判断；入库时把它做一遍，查询时仍要核对一遍。回看窗口、预测长度、切分约定等条件同理，按锚点读原文判断，不在结构中复述。上一版的 `cond_split` 与切分约定（领域配置 `ltsf-autoformer`）一并退出首版。行级入库（`f95631b`）与按表入库（`781832d`）保留为日后对照。

## 5. 数字从哪来：由 `CITES` 承担（已定，2026-10-03 修订）

上一版在每条参与边上记录 `origin`（`own` / `rerun` / `cited` / `unstated`）及其依据和出处。改为按组录入后，同一组里同一基线的来源可能不一致（PatchTST 的 FEDformer 在表 3 中是重跑，在附表 15 中引自 DLinear 论文），逐项记录又回到逐表细抠。因此：

- 参与边不记来源性质。
- 论文结果对另一篇论文的依赖写成 `CITES`（第 8 节），`description` 写明哪些实验、哪些方法的结果引自该论文，例如 "Results of DLinear, Pyraformer and LogTrans in Table 3, all baselines in Table 8 … are collected from this paper"。发现的入口是这条边：从它就知道两篇论文的结果相互依赖、该去读哪里。
- 必要时在实验描述中一句话说明（"Baseline results are collected from …; FEDformer, Autoformer and Informer are re-run with six look-back windows"）。
- 某个数字是不是转引、两份结果是不是同源，由 Agent 按锚点读原文判断。数值相同不能推出转引：行级试写中发现的 5 条跨论文同值线索里，2 条是三位小数的巧合。

## 6. 照抄名称，不入库疑点（已定，2026-10-03；2026-10-03 修订）

- 名称按原文印的写。Agent 的规范化（如把 "Eletricity" 对应到 Electricity）通过引用绑定表达：`{id, printed: Eletricity}`；笔误不注册为 alias，确实是新叫法才 `register`。
- 精确键区分大小写，参考文献中的标题常与论文本身的大小写不同（PatchTST 参考文献中的 "Are transformers effective for time series forecasting?"），按名称引用不会命中。此时按参考文献给出的标识（arXiv:2205.13504）确认后用 `{id: paper_0001, printed: …}` 绑定，同样不注册为 alias。
- **疑点与评价不入库（首版）。** 原文自相矛盾、疑似印错（如 DLinear 表 4 中 ILI 的预测长度印作 96–720）是入库者的判断，不是论文的陈述。写进实验节点会被读者当成原文内容（第 4 节的试跑证据）。这类判断要入库，须作为带作者与依据的独立记录（Q1，Agent 判断的持久化）；在此之前不写。
- 编译时核对称呼：表单里的方法名、数据集与指标的称呼，必须出现在该实验某个锚点的行范围内，否则列为待确认。

## 7. 引用已有对象与外部否定（已定，2026-10-03）

| 写法 | 用途 | 编译行为 |
| --- | --- | --- |
| `{mention, kind}` | 引用已有对象 | 只走 id 与 alias 两级，唯一命中才通过；否则在 dry_run 中列为待确认，apply 拒绝整批 |
| `{id, printed?, register?}` | 已确认指向的引用 | `printed` 是原文印的称呼；`register: true` 时注册为新 alias |
| `new` + `rejected: [id…]` | 新建对象 | `Resolve(write)` 返回的语义近邻，必须由 Agent 逐个列入 `rejected`（判断为不是同一对象） |
| 表单内 `ref` | 本批对象互相引用 | — |

- `rejected` 只记录同一性的否定，**不顺带写方法间关系**（第 1 节）。查重时看到的近邻（如 PatchTST 的近邻 Patching、Channel independence）可能确有关系，但不在单篇抽取中包办；`rejected` 留下的"当时看过哪些候选"，留作以后 I1 / I4 实例判断要不要补关系的材料。
- 桩节点的查重只走 id、alias 与名称词面通道，不跑向量通道。桩节点只有名称，向量召回的几乎全是通用概念；名称词面的模糊匹配仍能抓到拼写变体（如参考文献中的 "Fedformer"）。
- 引用的对象应由先前批次建立而那一批尚未提交时，先提交那一批，不要从语义候选中挑选。
- 外部否定的次数是主张 A 构建成本的测量项。语义阶段不设阈值，每个新对象的近邻数由 `TOP_N` 决定，不代表真实歧义；要统计的是 Agent 实际花在否定上的判断。

## 8. 引用关系：选择性写入（已定，2026-10-03）

每条引用都写 `CITES` 并说明原因，代价过高，而且多数引用只是背景。首版只写对本文的方法、主张或实验**有实质支撑**的引用：

| 档 | 条件 | 处理 |
| --- | --- | --- |
| 必写 | 本文报告的结果有一部分引自这篇论文（原文声明） | Agent 判断；`description` 写明哪些实验或表、哪些方法的结果引自该论文 |
| 可写 | 对本文有实际作用：沿用其实验设置、方法建立在它之上、作为主要对照 | 由 Agent 选择；依据须包含正文中的引用位置 |
| 不写 | 背景、综述性引用 | — |

- 表单写法：`relationships` 中的 `{from: paper, type: CITES, to: <Paper ref>, basis: [<定位>…], description?}`。论文表单只允许这一种关系，起点只能是本文。
- `basis` 至少要有一处参考文献节之外的位置：参考文献条目只能说明"引用过"，正文中的引用位置才说明引用在哪里起作用。参考文献条目可以一并列出，便于核对出处。
- `description` 用一两句话写这条引用支撑了什么，例如 "Results of DLinear, Pyraformer and LogTrans in Table 3 … are collected from this paper"。不设引用意图的枚举。
- 入库后边上存 `source_refs`（`<material_id>::<定位>`）与 `description`（[Graph Model V2](./graph_model_v2.md) §6.2.3）。
- 被引论文只建桩节点（第 1 节），名称按参考文献印的标题，`note` 写引用线索。它本身入库时如何与桩节点合并，见第 10 节。
- **没有 `CITES` 不等于没有引用**，与第 9 节的覆盖声明同理：图中的 `CITES` 是本文实质依赖的子集，不能用来统计引用数或判断两篇论文无关。

## 9. 范围声明（已定，2026-10-03；2026-10-03 修订）

- 每篇论文结果部分的**全部研究问题**都录成 Experiment，包括只用图报告的实验，不只首个 I3 实例用到的那几组。
- 每批写明录了哪些实验及其锚点（批次记录的 coverage）；没有录入不等于原文没有报告，不能把缺失读作否定。
- 首版不抽 Claim、Usage、Assessment；实验描述中的结论写成"论文声称"，不作为已核验的 Claim。
